# Awakening Eden release verification protocol

Owner direction: Sofia, 7 October 2026. Apply this before and after every website release.

## Before editing

1. Read the newest owner decision, visual lock and applicable implementation plan.
2. Compare three states: the actual public pages at `https://awakeningeden.org`, the current GitHub `main` production source, and the local working tree.
3. Preserve newer approved work and unrelated local files. Resolve divergence before editing or publishing.
4. Classify each requested item as already live, a genuine upgrade, blocked by missing context/permission, or no longer needed. Implement only the genuine upgrade.
5. Keep real projects, process photographs, concepts and general inspiration visibly distinct. Preserve the exact twelve-fold Lotus rule.

## Before publishing

1. Run the production build, zero-cost guard, visual-lock check and diff check.
2. Check desktop and phone layout for the changed experience when browser preview is available.
3. Verify every new asset exists and every primary action has a real destination.
4. Reconcile the production branch without overwriting newer remote work.

## After publishing

1. Record the production version or commit.
2. Request the actual public routes and confirm successful responses.
3. Search the returned public HTML for the new headings, actions, labels and important links; do not treat a successful build as proof of publication.
4. Compare the public result with the approved plan and report three honest groups:
   - live and verified;
   - intentionally still planned;
   - waiting for owner context, permission or a source asset.
5. Do not describe a plan, local preview or pushed source as live until the public-domain check passes.
